Scope#

In scope / out of scope, as two short lists. Name the area that owns each out-of-scope item.

Architecture#

Layers and module boundaries as a table: layer | module | class | responsibility. State the technology split where one exists (contract module versus engine implementation).

Design Patterns (→ patterns.md when the README would exceed 130 lines)#

Only patterns that change how a reader must write code here, and only patterns specific to this area — repo-wide patterns belong in .claude/knowledge/PATTERNS.md. For each: pattern name, the concrete classes that implement it, and the rule a contributor must follow to extend it (for example: "new strategy = register in StrategyStore, extend AbstractStrategy"). Reference .claude/knowledge/PATTERNS.md for repo-wide patterns instead of repeating them.

Flow#

One ordered table from entry point to terminal state — no second table for envelopes:

HopConditionEnvelopeMutates

Anchor hops with Class#method, not line numbers. Name the serialization boundary (queue topic, REST body, search document) and the type on each side in the envelope column.

Config / Forks (→ contracts.md)#

SettingLookupValuesBehavior per value

Include method-argument flags that pick a branch, not only tenant or environment settings. Every row must name the class and method where the fork is read.
