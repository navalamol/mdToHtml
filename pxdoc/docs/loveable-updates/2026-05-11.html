UX Changes by Domain#

Dashboard#

  • KPI density toggle. A pair of Toggle controls ("Compact" / "Comfortable") is rendered above the KPI grid on the dashboard. State persists to localStorage under key kpi-density (default compact). Selected density is passed to each KPICard as the new density prop.
  • Shrunken KPI cards. KPICard now accepts density?: "compact" | "comfortable" (default compact). Compact mode uses smaller padding (p-4 vs p-6), smaller title (text-xs), smaller value (text-lg vs text-2xl), smaller arrow/lightbulb icons (h-3.5 vs h-4), tighter divider (mt-2 pt-2 vs mt-4 pt-4), smaller AI suggestion text (text-xs) and a shorter "View Details" button (h-6 px-1.5 text-[11px]). The unused Badge import was removed.
  • CRO KPI tiles added. Four new KPI keys are prepended to the default KPI grid: conversionRate (3.42%, success), addToCartRate (11.8%, success), cartAbandonment (62.1%, destructive), avgOrderValue ($84.20, success). All four currently route to /insights/sku-performance. New labels added to KPI_LABELS.
  • CRO Metrics widget. New widget CROMetricsWidget rendered conditionally (croMetrics.visible) below the ordered widget list on the dashboard. Inside:
    • A 2/3-column grid of 6 metric tiles (Conversion Rate, Add-to-Cart Rate, PDP Bounce Rate, Cart Abandonment, AOV, Revenue per Visitor) each with icon, value, delta with up/down arrow tinted success/destructive, and optional hint.
    • A "Conversion Funnel" panel with four Progress rows (Product views 100% → Added to cart 11.8% → Reached checkout 6.4% → Completed purchase 3.42%) plus visitor count.
    • An "Active A/B Experiments" panel listing three experiments with lift % and Winning/Losing badge.
    • An "AI insight" call-out (primary-tinted card with Sparkles icon) with a recommendation example.
    • A "View CRO Analytics" outline button navigating to /insights/sku-performance.
  • Widget config order shift. croMetrics inserted at order 8; recentActivity and quickActions shifted to 9 and 10. WIDGET_LABELS.croMetrics = "Conversion Rate Optimization".

Implementation Notes#

  • BY Network needs API + permissions. Loveable's page uses hard-coded PRODUCT_DATA and an in-memory cart. For pxc-retail this would need:
    • A new top-level route (likely outside _shell since it is full-screen with its own header) or a sibling layout.
    • oRPC contracts under @repo/core-contracts for catalog item listing, filtering, vendor availability, and order/cart creation. Until the BFF exists, mock fixtures should match the loveable shape.
    • A permission key in src/lib/permissions/ (e.g. by-network) so the menu entry and route are filtered for unauthorized users — loveable's AuthGuard is coarser than pxc-retail's requireModuleAccess.
    • Branding tokens: loveable scopes the navy brand by overriding --primary inline. In pxc-retail this should be done via the Tailwind 4 / OKLch token system (globals.css) on a wrapper class rather than inline style.
  • Design-system mappings. Loveable uses HoverCard, Sheet, Toggle, Progress, Checkbox, Select, Badge, Card, Input, Button, DropdownMenu. All exist in @syndigo/design-system/components/*; verify variants match (@base-ui/react primitives vs. shadcn defaults).
  • Image assets. blueyonder-logo.png is new in loveable. Add as apps/pxc-retail/src/assets/blueyonder-logo.png if BY Network is implemented.
  • i18n is required. Every loveable string ("Search Results", "Add To Cart", "Shopping List", "Conversion Funnel", "AI insight", filter labels, density toggle labels, etc.) must be moved into apps/pxc-retail/src/locales/{en,es,fr,de}/translation.ts. Hard-coded text is not allowed per CLAUDE.md.
  • Dashboard config store. Loveable uses useDashboardConfigStore (src/lib/dashboard-config-store.ts) with localStorage-backed visibility/order + KPI list. pxc-retail has no equivalent yet; if dashboard is to be built, decide whether to mirror that store or move config to user-prefs via oRPC.
  • Routing convention. TanStack Router file-based routing in pxc-retail will need src/routes/_shell/by-network.tsx (or a route outside _shell if the custom chrome is preferred). Remember routeTree.gen.ts is autogenerated.
  • Density preference. Loveable persists per-browser via localStorage. In pxc-retail consider whether this belongs on the user record (oRPC) for cross-device parity.
  • Routes referenced by new KPIs. All four new CRO KPIs target /insights/sku-performance, which does not exist in pxc-retail (_shell/insights/ only contains content-quality.tsx). Either create the route or repoint the KPIs.
