## UX Changes by Domain

### Validation Framework (new)

A self-contained, client-only rule engine under `src/lib/validation/` plus four shared React components, wired into the vendor record editor and the new-vendor request flow. No Zod, no server — pure functions returning a `RuleResult { id, severity, message, trigger, section, field }` envelope.

- **Shared components:** `ValidationSummaryBanner` (sticky `role="alert"` "N errors, M warnings" with buttons that scroll+focus the offending field via `data-testid`); `FieldMessages` (`FieldError`/`FieldWarning`/`FieldHint` + `RequiredSrLabel` + `errorInputClass`); `AddressFields` (validated Country→Street→City→State/ZIP block with normalize-on-blur, aria wiring, subdivision selects); `ValidationDebugDrawer` (dev-only `?debug=1` Sheet listing pass/fail for the full rule catalog).
- **Shared behaviors:** `canSave` (errors block Save; warnings require acknowledgement), `shouldShow` (messages appear only after touch or a save attempt), `normalizeText` (trim + collapse whitespace), stable `field-<section>-<name>` / `msg-<section>-<name>` test-ids.
- **Validators:** ABA checksum, IBAN mod-97, SWIFT/BIC, EIN prefix + placeholder detection, DUNS, GS1/GLN check digit, SCAC, postal, E.164 phone (libphonenumber-js), email, https URL, 4-digit year.
- **Per-section schemas:** `vendorProfile` (VP-001..015), `banking` (BK-001..018 + TX tax + TT trade terms), `businessRisk` (BR-001..027 D&B identity/hierarchy/scores/ownership/diversity), `addresses` (AD-001..025 incl. PO-box ban, sanctioned-country block, GLN, cold-chain, FFR), `contacts` (CT-001..014), `documents` (DC-001..019 incl. COI/FDA/GFSI/W-9 metadata, DocuSign), `customFields` (GEN/CP — ESG, attestations, SCAC, GDSN), `onboarding` (OB-001..005 approve/reject gates + segregation-of-duties), `newVendorRequest`, and `rules.ts` (XS-001..010 cross-section integrity on save).
- **Mocks:** `mockServices.ts` client-side stubs (explicitly server-side TODOs) for routing lookup, duplicate-vendor, sanctions, TIN match, DUNS, address verify, malware scan, carrier authority; `audit.ts` mock RBAC + activity log; `config.ts` D&B/insurance/sanctions/disposable-domain data.

### Vendor Central

- **Vendor List:** fixed **20/page numbered pager** with "Showing X–Y of N (filtered from M)"; seed grew 10→26 vendors. Sort dropdown gained **Category/Location/Status**; default changed trustScore/desc → **name/asc**; column headers became **clickable sort buttons** with `aria-sort` and ▲/▼/↕. View mode persisted to localStorage per-user; full list state saved to sessionStorage and **restored on browser Back** only. **Inactive**/**Blocked** statuses + semantic badge colors. Search **trims whitespace**; new removable **Trust Score range** chip; capability "+N more" **hover tooltip**; new **Order Volume** ($X.XM) on cards; `?highlight=VND-nnn` jumps/scrolls/ring-highlights.
- **Request New Vendor:** new **Legal Name** + **D-U-N-S** fields with field-level validation + summary banner. **Duplicate check** on submit (`findProbableMatches` normalizes names/DUNS) opens a "Possible duplicate vendor" dialog offering **Merge** or edit. **"List on Approval"** creates/merges via `addNew` then routes to All Vendors with `?highlight=`.
- **Vendor Network:** accepting a request / confirming matches runs the same dedup and **toasts "probably already exists … not added again."**
- **Vendor Profile:** **bank-change dual approval** (`PendingBankChange` in localStorage; Current vs Requested masked; second approver, `canApproveBankChange` blocks self-approval, callback-verification checkbox, ≥10-char reject reason; account number write-only). **Payment-terms** change on Active requires reason + "Needs approval." New **Remit-To / Billing address** change control (≥10-char reason + dual-approval warning). **PII reveal hardened** — bank/Tax ID/insurance/contact reveals are permission-checked (`pii.reveal`/`bank.reveal`/`contact.reveal`/`compliance.reveal`) and **written to the activity log**.
- **Things to Fix:** "all clear" empty state; each failing field carries `testId`/`docId` so **Fix** focuses the exact input/document; BC-03 now distinguishes "no primary marked" from "no contacts."
- **Section nav / review:** per-section **error-count badges**; warning-toned TIN badge; Documents gained **Awaiting-review / Approved / Rejected** statuses with reviewer **approve/reject (reason)** actions, review filter, and preview activity logging.
- **Onboarding workflow:** stage Approve/Complete/Reject gated by aggregated blockers — unresolved validations, `approvalBlockers`, financial-step block, and **segregation of duties** (can't approve what you created/last edited); reject requires 10–500 chars; decisions fire `onDecision` for audit.

### Admin & Roles

- **`merchant` role renamed to `vendor`** everywhere; legacy `"merchant"` maps to `"vendor"` on login. Vendor modules narrowed to `["vendor-portal", "product-catalog"]`; `merchandising` **gains** `vendor-portal`.
- **New `assignedVendorId`** on user/auth state (seed Maria Rodriguez → `vendor` / `VND-008`; default `VND-008`). New `canVendorOpenPath()` allows a vendor only `/vendor-portal/<their id>` and `/product/<id>` where the product's vendor matches.
- **New "Vendor Settings" admin sub-tab** (`Admin.tsx`): Business-Admin system setting listing **required address types** as checkboxes, persisted via the new `address-config-store` (default `["HQ","Billing"]`, localStorage).
- RoleAdmin default create role merchant→vendor; `hasModuleAccess` hardened with a `!def` guard.

### Layout & Navigation

- **Retailer Flow moved out of the top menu into Admin** as a sub-tab (`/retailer-flow`); path/sub-tab resolvers updated. `vendor-settings` sub-tab also added under admin.
- **Real No-access screen** in `AuthGuard` (was a silent redirect to `/`): full `role="alert"` `data-testid="no-access"` panel with "Go to my vendor record" (vendors) + "Go to Dashboard"; guard now also blocks vendors via `canVendorOpenPath`.
- **MenuBar** relabels Vendor Management → **"My Vendor Profile"** for vendors (navigates to their record). **Breadcrumbs** collapse to first+last crumb for vendors in the vendor-portal module. **Header** adds the `vendor` role label.
- `previewAuthStorage.ts` — Lovable-preview auth-broker refactor; infra only, no pxc analog.

### Product Detail & Catalog

- **LocaleSelector** re-modeled from a flat two-list picker into a three-level **syndication context** (Country → Channels → Languages) driven by a `CONTEXT_RULES` table (US/CA/UK/MX); channels/languages filtered + pruned by selected countries; new trigger format ("US +1 · Walmart +2 · English (US)"), info hint, chips, "Apply context."
- **NextBestActionBar** gains a **collapsed default** — compact "Next step" bar (severity dot, truncated title, blocker badge, CTA, **Ask AI**, Show details); "Nothing outstanding — retail ready" when clear.
- **ProductCatalog vendor scoping:** `?vendor=` param + role gating — `role === 'vendor'` users see only their `assignedVendorId` products; create/import actions hidden for vendors. Store adds `vendorId`, `PRODUCT_VENDOR_MAP`, filter helpers.
- **ProductDetailPage "Ask AI"** now opens the `content-copilot` agent seeded with product context + quick-action chips.
- **PDP summary** role preset key `merchant` → `vendor` in `ROLE_DEFAULT_PRESETS` and settings role options.

### Data / Schema (reference only — pxc-retail uses oRPC/upstream, not Supabase/Drizzle)

- New `added_vendors` table: `id` TEXT PK matching `^VND-[0-9]{3,}$`, `name` (not null), `legal_name`, `duns`, `category` (default 'Uncategorized'), `status` (default 'Pending'), `trust_score` int, `location`, `on_time_delivery`, `order_volume`, `source` CHECK `'manual'|'network'`, `created_at`. Added to `supabase_realtime`.
- RLS migration `0001` drops public read; restricts SELECT to authenticated (`auth.uid() IS NOT NULL`); revokes `anon` SELECT; **anon insert stays open**. `supabase/types.ts` regenerated for the new table (plus a `PostgrestVersion` 14.5→14.1 regeneration artifact — ignore).
- `AGENTS.md` codifies two product rules: vendor-wide settings live in `src/lib` stores edited only in *System Administration > Vendor Settings*; approval-held changes (bank changes) are pending requests applied only on approval by a **different** user (dual control). `roadmap.md` is a guide-authoring checklist — no new product direction.

## Implementation Notes

- **Architecture divergence (the recurring theme).** Loveable persists runtime state client-side — Zustand stores (`added-vendors-store` + Supabase realtime, `bank-change-store` + localStorage) and per-user local/sessionStorage for list state — and ships one monolithic client-only `RuleResult[]` engine with English strings baked in. pxc-retail is contract-first: data flows through oRPC (`orpc.vendorCentral.tenantVendor.*`) with cursor pagination and `@repo/core-contracts/schemas/vendor-schema`; validation rules are pure functions in `core-contracts/vendor-central/*` returning `{ field, ruleId, key }` resolved to text via i18n selectors. **Any port of VP/BR/TT/TX/CP rules must follow that split** (rules in core-contracts, messages as `ErrorKey`/translation selectors) — Loveable's inline strings would violate the i18n rule in CLAUDE.md.

- **Backend-first posture / mocks → tickets.** pxc already annotates `banking-rules.ts` as interim pending RPC-150 and defers ZIP-vs-state, GLN, address verify, TIN uniqueness, ABA/sanctions/DUNS lookups to the backend. Loveable's `mockServices.ts` is the client stand-in for exactly those; in pxc they stay oRPC procedures, with warning inputs populated from server data. Per the "ticket every mock" rule, any new async check gets a Jira ticket + backend discussion.

- **Contract-shaped gaps to extend before porting:**
  - **Pagination:** Loveable's 20/page numbered pager vs pxc's cursor `useSuspenseInfiniteQuery` + "Load more" — needs a page/offset contract param or client slicing (backend exposes `nextCursor` only).
  - **Sort:** `VendorSortFieldSchema` only offers name/createdAt/employeeCountEstimate — category/location/status/volume/trust-score sort + clickable headers require contract + server extension.
  - **PII-reveal auditing:** Loveable introduced finer `pii.reveal`/`bank.reveal`/`contact.reveal`/`compliance.reveal` permissions + reveal audit-logging; pxc gates only `vendor-management:write` and does not log reveals — a gap if reveal auditing is required.

- **Biggest net-new clusters for pxc** (each backed by a Loveable `validation/schemas/*` with no pxc counterpart, and most needing new BFF fields):
  1. Business Profile & Risk / D&B validation (BR-001..027) — only compliance badges exist today.
  2. Trade Terms (TT) + Tax Identifiers (TX) rule validation — dialogs exist but validate nothing.
  3. Custom Fields / ESG / attestations (CP/GEN) — absent entirely.
  4. Cross-section (XS) + onboarding approval/SoD (OB) — absent.
  5. Request-new-vendor + duplicate/merge flow, Things-to-Fix business-validation engine + section error badges, onboarding reviewer workflow with segregation-of-duties, document reviewer approve/reject, and address-change dual approval.

- **Vendor self-scoping stays blocked.** The whole `vendor` role + `assignedVendorId` + `canVendorOpenPath` + "My Vendor Profile" + breadcrumb-collapse + catalog `?vendor=` cluster depends on the session exposing `role`/`assignedVendorId`, which pxc does not have (RPC-142 deferred to RPC-134). Only permission-gating works today; the `merchant`→`vendor` naming is worth aligning in pxc's role vocabulary if/when that lands.

- **Design-system mappings.** Loveable raw shadcn (`@/components/ui/*`) → `@syndigo/design-system/components/*` (no barrels): Tooltip → **Popover** for "+N more"; `Badge variant=outline` → pxc status-variant helper; `FieldError/FieldWarning/FieldHint` → design-system `Field`/`FieldError` (errors only today); `ValidationSummaryBanner` has no pxc equivalent (current pattern is focus-first-error + `*WarningsDialog` acknowledge dialogs); `AddressFields` → composed `AddressDialog` + `CountryCombobox`/`StateProvinceField`. Reusable validators (ABA, IBAN mod-97, EIN prefix/placeholder) already exist in pxc `banking-rules.ts` — reuse rather than re-import.

- **Ignore for pxc:** `previewAuthStorage.ts` (Lovable-preview infra), the `supabase/types.ts` `PostgrestVersion` 14.5→14.1 regeneration artifact, `.lovable/*`, `drizzle/*` (reference data shape only), and `bun.lock`/`package.json`.
