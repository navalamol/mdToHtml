## UX Changes by Domain

### Auth / Roles

- Auth store now defines 3 roles: `business-admin`, `merchandising`, `merchant`, each with a `modules` allow-list.
- Login resolves against a dynamic `useUsersStore` (Zustand + localStorage) falling back to static seed users. `sarahchen` (Merchandising), `retailpxcadmin` (Business Admin), `mariarod` (Merchant) are pre-seeded.
- `hasModuleAccess(moduleKey)` checks the dynamic `role-feature-store` first, then falls back to static role definitions.
- Welcome toast on login is now generic ("Welcome back!").

### Shell / Navigation

- `AuthGuard` now resolves the current path to a `moduleKey` (via `getModuleFromPath`) and redirects to `/` if the user lacks access — no "access restricted" screen.
- `MenuBar` filters `menuGroups` by `hasModuleAccess` so inaccessible top-level items are hidden.
- `Header` user-avatar chip now shows dynamic `initials` / `displayName` / `roleLabel` from auth store. Business Admin users see a "Roles & Users" item in the user dropdown linking to `/role-admin`.
- Two new routes: `/role-admin` (Business Admin only) and `/admin/pdp-summary` (Business Admin only).

### Admin

- New `RoleFeatureTogglePanel` component: a two-column layout — left column toggles per-role module+sub-feature access, right column is a live nav preview. Business Admin role locks all toggles (always full access). Changes persist to `localStorage` via `role-feature-store`.
- `Admin.tsx` Roles & Permissions tab gains a new "Role Feature Toggles" sub-tab (default), and "Feature Enablement" is renamed "Org Feature Enablement".
- New `/role-admin` page (`RoleAdmin.tsx`): two-tab card — "Users" tab (full user management table with create/role-change/reset-password/delete) and "Role access" tab (embeds `RoleFeatureTogglePanel`). Guards: redirect to `/auth` if unauthenticated, show a locked-out message for non-Business Admin.
- New `/admin/pdp-summary` page (`PdpSummarySettings.tsx`): Business Admin sets per-role default widget layouts for the PDP Summary tab (toggle visibility, reorder with up/down arrows, save/reset per role).

### Product Detail Page (PDP)

- Tab now defaults to `summary` (was `attributes`). Active tab is URL-driven via `?tab=` search param; switching tabs clears deep-link context params.
- New "Summary" tab renders `ProductSummaryTab`: a configurable 2-column widget grid with up to 9 widgets — Things To Do, AI Recommendations, Quality & Completeness, Workflow Status, Attributes Summary, Assets Summary, CRO Metrics, Ratings & Reviews, Relationships. A "Configure" dropdown lets users toggle visibility and reorder widgets; config is persisted per-role per-product via `pdp-summary-store`. Users can reset to role defaults. Business Admin sets role-level defaults via `/admin/pdp-summary`.
  - All widget rows deep-link to the correct PDP sub-tab with context params (e.g., `?tab=assets&filter=missing&type=hero`).
  - AI Recommendations includes two GEO/AEO entries linking to the new Commerce Optimization tab.
- New "Commerce Optimization" tab (`ProductCommerceOptTab`): GEO score card, AEO score card (both with Progress bar + pass/warn/fail counts), GEO Optimizer sub-tab (audit checklist + "Generate optimized content" button with simulated output), AEO Optimizer sub-tab (audit checklist + "Generate FAQ + speakable" button), and Channels sub-tab (per-channel scores for Google AI Overviews, Perplexity, ChatGPT Search, Alexa/Siri, Featured Snippets, Bing Copilot).
- Workflow panel (right column) is now **collapsed by default**, showing a single expand-button. Expanding it shifts center content from 8 → 6 cols and the panel from 1 → 3 cols.

### Vendor Portal

- `navigation-config` adds a new sub-tab entry `vendor-network` ("Syndigo Vendor Network") to the `vendor-portal` module's `moduleSubTabs`.
- "Add New Vendor" button is now a dropdown with two options: "From Syndigo Vendor Network" → activates the `vendor-network` sub-tab, "Add Manually" → activates the existing `onboarding` sub-tab.
- New `VendorNetworkTab` component: hero card with CTA "Continue to Product Intake Onboarding" (navigates to `/vendor-product-onboarding?tab=vendor-onboarding`), then embeds the existing `VendorSearch`, `RecommendedVendors`, and `VendorBulkUpload` components.
- `VendorOnboardingTab` gains a context banner at the top explaining vendors added in Vendor Management appear here for product-intake onboarding.

## Implementation Notes

**Role-based access control**

- `pxc-retail` uses `requireModuleAccess` in `beforeLoad` guards and `useFilteredMenuGroups`/`useFilteredSubTabs` for nav filtering. The loveable reference uses `hasModuleAccess` from `auth-store` + a `role-feature-store` (zustand/persist).
- The equivalent in pxc-retail should wire the dynamic per-role toggle overrides into the existing `permissions` oRPC module or a new local store, then expose them via `useFilteredMenuGroups`.

**PDP Summary tab**

- `ProductSummaryTab` accepts `onNavigateTab(tab, context)` for deep-linking — pxc-retail's tab navigation is URL-driven via TanStack Router's `useNavigate` + search params. Wire the `onNavigateTab` prop to update `?tab` and any context search params using `useNavigate` from TanStack Router.
- `usePdpSummaryStore` uses zustand/persist; pxc-retail should implement an equivalent using server-side persistence if layout preferences need to survive across devices/sessions, or keep it client-local.
- `pdp-summary-store` exports `ALL_SUMMARY_KEYS`, `SUMMARY_WIDGET_LABELS`, `SUMMARY_WIDGET_DESCRIPTIONS`, and `SummaryWidgetKey` — all needed by both `ProductSummaryTab` and `PdpSummarySettings`.

**Commerce Optimization tab**

- Currently all-simulated (static scores, fake async delay for generation). Integration point: replace `runGeoOptimizer`/`runAeoOptimizer` with real AI API calls once the backend endpoint is available.
- `initialMode` reads `?mode=geo|aeo` from search params — the Summary tab AI Recommendations deep-link already sets this.

**Vendor Network tab**

- Reuses existing `VendorSearch`, `RecommendedVendors`, `VendorBulkUpload` components — check if these exist in pxc-retail's vendor domain.

**Design system**

- All components use shadcn primitives already mapped to `@syndigo/design-system`: `Card`, `Badge`, `Button`, `Switch`, `Tabs`, `Progress`, `ScrollArea`, `Textarea`, `Table`, `Dialog`, `Select`, `DropdownMenu`, `Label`, `Input`.
- Color usage: `text-secondary`/`bg-secondary` for positive/pass states, `text-warning` for warn states, `text-destructive` for fail/error states — confirm token names match pxc-retail's OKLch token mapping.
